# データ設計

保存形式の正本です。変更範囲と論点は [設計標準](../standards/design-and-documentation.md#architecture-method) に従って会話で提示します。

データベースは使いません。取得した利用状況は保存しません。利用者が選択した取得元、Hub接続設定、表示先、スタイル、反転、サービスの表示内容とスキップ、個別枠の選択、巡回、離席判定の設定は、1つのJSONファイルに置きます。ほかに、新版の適用まで、取得したインストーラーを一時的に置きます。また、同梱の tokscale が使う設定・解析キャッシュを専用のディレクトリに置き、ローカル取得で監視する探索先を探索先ファイルに置きます。組み込み以外の表示スタイルは、指定フォルダーのコピーとして専用のディレクトリに置きます。

## 設定ファイル

配置はユーザーごとの設定領域のアプリ ID 配下で、`%APPDATA%\io.github.nuitsjp.token-monitor-turzx\settings.json` です。環境変数 `WAILS_DATA_DIR` を指定した場合は、そのディレクトリ直下に置きます。

| キー | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `source` | 文字列 | 新規保存時は必須 | 取得元の `Local` または `Hub`。既存ファイルにない場合は `Local` として扱う |
| `connection` | 文字列 | `Hub` のとき必須 | 接続先 URL と認証トークンを `{"url": "…", "token": "…"}` の JSON にまとめ、Windows の DPAPI（`CryptProtectData`、現在のユーザー単位、追加のエントロピーはアプリ ID）で暗号化し、Base64 にした値。`Local` の初回保存では省略できる |
| `displayID` | 文字列 | 必須 | 表示先に選んだ TURZX の機器の識別子。`Automatic` のときは空文字列 |
| `displayName` | 文字列 | 必須 | 表示先に選んだ TURZX の表示名（例: `TURZX1.0 (633A6E01)`）。機器が接続されていない間も選択肢に表示するために保存する。`Automatic` のときは空文字列 |
| `limitStyle` | 文字列 | 任意 | 選択したスタイルのID。未設定は`gauges`。既存の`Gauges`と`Bars`はそれぞれ`gauges`と`bars`として読む。適合していれば既存文字列を保持し、手動変更または[自動補正](../usecases/利用状況をUSBディスプレイに表示する/scenarios/3.5インチでサービスごとの利用枠を順番に表示する.md#表示先と向き)が必要なときにIDを保存する |
| `presentation` | オブジェクト | 任意 | 下表の表示設定。未設定は反転OFF、更新時の消灯OFF、スキップOFF、サービス設定なし |
| `hiddenLimits` | 文字列の配列 | 任意 | 表示しないと選んだ枠の識別子。枠は `provider`・`accountLabel`・`kind`・`label` を U+001F（単位区切り文字）でつないだ文字列で識別する。既存ファイルにない場合は空（すべて表示）として扱う |
| `cycle` | 真偽値 | 任意 | 9.2インチ用スタイルで表示しきれない利用枠を順番に切り替えるか。既存ファイルにない場合は `false` として扱う。3.5インチ用スタイルには適用しない |
| `cycleSeconds` | 整数 | 任意 | 9.2インチ用スタイルで各ページを表示する秒数（5〜3600）。既存ファイルにない場合、または範囲外の場合は 10 として扱う |
| `serviceCycleSeconds` | 整数 | 任意 | 3.5インチ用スタイルで各ページを表示する秒数（5〜3600）。4つの標準スタイルと、同じサービス表示データを使う追加スタイルで共通とし、取得元や表示先ごとには分けない。既存ファイルにない場合、または範囲外の場合は 10 として扱い、`cycleSeconds`から引き継がない |
| `awayMinutes` | 整数 | 任意 | 離席と判定する、キーボード・マウスの無操作時間（1〜240分）。既存ファイルにない場合、または範囲外の場合は 10 として扱う |

`presentation`は実行時の`display.Presentation`と同じ構造です。

| 項目 | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `reverse180` | 真偽値 | 任意 | 180度反転。未設定は`false`。全体設定であり、機器別には保存しない |
| `blankOnUpdate` | 真偽値 | 任意 | 3.5インチの更新方式。未設定と`false`は消灯しない全画面の逐次更新、`true`は消灯中の差分転送と点灯。3.5インチの全スタイルで共有し、9.2インチでは適用しない。表示先を変えても保存値を保持する |
| `skipFull5h` | 真偽値 | 任意 | [表示シナリオ](../usecases/利用状況をUSBディスプレイに表示する/scenarios/3.5インチでサービスごとの利用枠を順番に表示する.md#スキップと対象がない場合)の条件で、5h残量100%または表示対象の利用枠がないサービスをスキップする。未設定は`false` |
| `services` | オブジェクト | 任意 | `Local`または`Hub`をキーとするサービス設定の辞書。各値はサービスIDをキーとする辞書。未設定のサービスはONかつBoth |
| `services[取得元][サービスID].enabled` | 真偽値 | サービス項目がある場合は必須 | ON/OFF。`false`も明記する |
| `services[取得元][サービスID].content` | 文字列 | サービス項目がある場合は必須 | `Both`、`Limits`、`Tokens`。OFFにしても保持する |

サービスIDは[表示シナリオ](../usecases/利用状況をUSBディスプレイに表示する/scenarios/3.5インチでサービスごとの利用枠を順番に表示する.md#サービスの選択)の識別規則に従います。サービス名、表示順、機器プロファイル、対応寸法、スタイル候補一覧は保存しません。

## 保存と読み込みの規則

- ファイルがないときは、取得元を `Local`、接続先 URL は空、認証トークンは未設定、表示先は `Automatic`、利用枠の表示スタイルは `Gauges`、9.2インチ用の切り替えは切、両方の切り替え間隔はそれぞれ10秒、離席と判定する無操作時間は10分として扱います。
- 保存は、同じディレクトリの一時ファイルへ書いてから置き換えます。置き換えに成功した時点を保存の確定とし、失敗したときは既存のファイルを残します。
- `Local` の保存では Hub の接続情報を要求しません。保存済みの `connection` があれば暗号化された値を保持します。
- `Hub` の保存で認証トークンの入力が空なら、保存済みのトークンを復号して、新しい接続先 URL と組にして暗号化し直します。
- ファイルを読めないとき、または復号できないとき（別の Windows ユーザーや別の PC でコピーしたファイルなど）は、エラーを返します。ファイルは上書きも削除もしません。
- 表示スタイルの保存は、取得元・接続設定・表示先の保存値を変えません。同じファイルの1回の置き換えで、ほかの項目は現在の値を保ちます。
- 表示設定の保存も同じファイルの1回の置き換えで確定し、成功後にだけ表示へ反映します。失敗した場合は設定、画像、現在ページ、巡回期限を保持します。型や選択値が不正な表示設定はエラーとし、既存ファイルを上書きしません。
- サービス設定は取得元別に保持し、一時的な欠落や取得元の変更では削除しません。個別枠の選択とは独立させ、別設定の保存でも未変更の値を保持します。Output変更に伴うスタイル補正は同じ1回の保存で確定します。起動時やAutomaticの接続先変更時の補正は`limitStyle`だけを更新し、取得元・暗号化された接続設定・表示先・各表示設定を保持します。補正不要なら書き換えません。
- 描画世代、巡回期限、開閉状態、利用状況、現在のCOM番号は保存しません。再起動時の現在ページは先頭です。参考ブランチ専用の設定移行や保存形式のバージョン管理は追加しません。
- 利用枠の選択は `hiddenLimits` だけに持ち、契約のチェック状態は保存しない。ファイルにない枠は表示する。一覧にない枠の識別子は、取得元の切り替えや一時的な欠落では消さない。選択の保存は、同じファイルの1回の置き換えで、ほかの項目を現在の値のまま保つ。
- 9.2インチ用の切り替えの有無と秒数、3.5インチ用の秒数の保存は、同じファイルの1回の置き換えで、ほかの項目を現在の値のまま保ちます。`cycle`を切にしても`cycleSeconds`は残します。範囲外の秒数は保存せず、エラーを返します。設定APIの`serviceCycleSeconds`は整数とし、保存要求で省略または0なら現在値を保持し、取得結果では既定値を適用した値を返します。
- `serviceCycleSeconds`が未設定であることを理由に起動時にファイルを書き換えず、既存の`cycle`と`cycleSeconds`を保持します。3.5インチ用の巡回ON/OFF、現在のページ番号、巡回期限は保存しません。
- 離席と判定する無操作時間の保存は、同じファイルの1回の置き換えで、ほかの項目を現在の値のまま保ちます。範囲外の分数は保存せず、エラーを返します。離席中かどうか、消灯中かどうかは保存しません。
- 接続先 URL と認証トークンの平文は、ファイルにもログにも書きません。

## 更新ファイル

配置は `%APPDATA%\io.github.nuitsjp.token-monitor-turzx\updates\update-<ランダムな名前>\<インストーラーのファイル名>` です。環境変数 `WAILS_DATA_DIR` を指定した場合は、そのディレクトリ直下の `updates` に置きます。更新情報（`update.json`）は保存せず、メモリにだけ持ちます。

- 起動後に新版の確認を始める前に、`updates` を中身ごと削除します。前回の起動で残ったファイルは使いません。
- インストーラーは新しく作ったフォルダーへ書き込み、サイズと SHA-256 のハッシュが更新情報と一致した時点で取得済みとします。失敗したときや途中で止まったときは、そのフォルダーを削除します。
- 適用の直前に、置いたファイルのサイズとハッシュをもう一度確かめます。一致しなければ適用しません。

## tokscale のディレクトリ

配置は `%APPDATA%\io.github.nuitsjp.token-monitor-turzx\tokscale\` です。環境変数 `WAILS_DATA_DIR` を指定した場合は、そのディレクトリ直下の `tokscale` に置きます。

- 取得元が `Local` のとき、アプリが実行する tokscale の子プロセスにだけ、環境変数 `TOKSCALE_CONFIG_DIR` としてこのディレクトリを渡します。アプリ自身のプロセスの環境変数は変えません。
- 中身の形式は tokscale が決め、アプリは読み書きしません。利用状況の集計結果をアプリが書き込むこともありません。
- 解析をやり直さずに済むよう、再起動や取得元の切り替えでは削除しません。ディレクトリがなければ、最初の実行の前に作ります。
- Cursor の認証情報と API のキャッシュは tokscale の仕様によりこのディレクトリの外に置かれるため、アプリは扱いません。

## 探索先ファイル

配置は `%APPDATA%\io.github.nuitsjp.token-monitor-turzx\local-scan.json` です。環境変数 `WAILS_DATA_DIR` を指定した場合は、そのディレクトリ直下に置きます。`tokscale clients --json` はログ全体を解析するため実行の負荷が大きく、その結果のうちローカル取得が使う部分だけを保存して、起動のたびに実行しないようにします。

| キー | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `paths` | 文字列の配列 | 必須 | 監視する探索先の絶対パス。`clients --json` が返した Cursor 以外の探索先のうち、取得時にフォルダーとして存在したもの |
| `clients` | 文字列の配列 | 必須 | 既知のツールの識別子。保存時点で `graph --no-spinner` の `summary.clients` に現れていたもの |

- 取得元が `Local` で起動したとき、ファイルがあれば `paths` を監視し、`clients --json` は実行しません。ファイルがないとき、または読めないときは `clients --json` を実行します。
- `clients --json` を実行したあと、最初に成功した `graph --no-spinner` の結果と合わせて保存します。保存は、同じディレクトリの一時ファイルへ書いてから置き換えます。
- `graph --no-spinner` の `summary.clients` に、`clients` にないツールが現れたら、新しいツールを使い始めたものとして `clients --json` を1回実行し、監視する探索先を入れ替えてから保存し直します。実行中や保存し直す前に重ねては実行しません。
- 起動時の `clients --json` が失敗したときは監視なしで動かし、次回の起動で取り直します。
- 利用状況の値は保存しません。取得元の切り替えでは削除しません。
- 既に使っているツールのログの置き場所が変わっても、ツールの一覧が変わらないので検知しません。このファイルを削除してアプリを起動し直すと、探索先を取り直します。

## 追加した表示スタイル

配置は `%APPDATA%\io.github.nuitsjp.token-monitor-turzx\styles\<id>\` です。環境変数 `WAILS_DATA_DIR` を指定した場合は、そのディレクトリ直下の `styles\<id>\` に置きます。`<id>` は、そのスタイルの `theme.json` の `id` です。

組み込みの[標準スタイル](../architecture.md#style-contract)は、このディレクトリには置きません。ビルドに含まれる定義のままです。

中身は、指定したフォルダー配下のコピーです。相対パスを保ちます。定義の `id` と `name` は、このコピーの `theme.json` の値です。索引ファイルは置きません。

- 検査に合格してからコピーします。不合格のときは、このディレクトリを作りません。
- `id` が組み込み、または既に追加された定義と重複するときは、コピーしません。
- コピーは、`styles` の下の一時ディレクトリへ書いてから、`styles\<id>` へ置き換えます。置き換えに成功した時点で、定義に加えたものとします。失敗したときは一時ディレクトリを削除し、既存の定義とファイルは残します。
- `id` が `styles` 直下の1つのディレクトリ名にならないときは、置き換えをせず、コピー失敗と同じ結果にします。
- 追加元のフォルダーを後から変更しても、このコピーは変えません。
- アプリの起動時に、`styles` 直下の各ディレクトリの `theme.json` を読み、定義に含めます。再起動しても残します。取得元の切り替えや更新では削除しません。
- 設定ファイルの `limitStyle` は変えません。
- 削除は、`styles\<id>` を `styles` の下の一時名へ移し、成功した時点で定義から取り除いたものとして一時名を削除します。移せなかったときは、既存の定義とファイルを残します。一時名の削除に失敗しても定義には戻さず、利用者にも知らせません。残った一時名は、次の一覧の読み込みで掃除します。組み込み6スタイルと選択中の追加スタイルは削除できません。選択の保存と削除の判定・確定は同じ設定ロックで直列化します。

外部コピーの`theme.json`は[取り込みシナリオ](../usecases/Styleを追加する/scenarios/Styleを追加する.md)の寸法と`dataLayout`に従います。設定キーは追加しません。選択の保存時だけ既存の`limitStyle`をIDで更新し、取り込み・削除では設定を変更しません。確定済みメタデータはメモリに保持し、起動時に内部コピーから復元します。
