# データ設計

保存形式の正本です。変更範囲と論点は [設計標準](../standards/design-and-documentation.md#architecture-method) に従って会話で提示します。

データベースは使いません。取得した利用状況は保存しません。保存するのは、利用者が設定画面で保存・選択した取得元、Hub の接続設定、表示先と利用枠の表示スタイルだけで、1つの JSON ファイルに置きます。ほかに、新版の適用まで、取得したインストーラーを一時的に置きます。また、同梱の tokscale が使う設定・解析キャッシュを専用のディレクトリに置き、ローカル取得で監視する探索先を探索先ファイルに置きます。

## 設定ファイル

配置はユーザーごとの設定領域のアプリ ID 配下で、`%APPDATA%\io.github.nuitsjp.token-monitor-turzx\settings.json` です。環境変数 `WAILS_DATA_DIR` を指定した場合は、そのディレクトリ直下に置きます。

| キー | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `source` | 文字列 | 新規保存時は必須 | 取得元の `Local` または `Hub`。既存ファイルにない場合は `Local` として扱う |
| `connection` | 文字列 | `Hub` のとき必須 | 接続先 URL と認証トークンを `{"url": "…", "token": "…"}` の JSON にまとめ、Windows の DPAPI（`CryptProtectData`、現在のユーザー単位、追加のエントロピーはアプリ ID）で暗号化し、Base64 にした値。`Local` の初回保存では省略できる |
| `displayID` | 文字列 | 必須 | 表示先に選んだ TURZX の機器の識別子。`Automatic` のときは空文字列 |
| `displayName` | 文字列 | 必須 | 表示先に選んだ TURZX の表示名（例: `TURZX1.0 (633A6E01)`）。機器が接続されていない間も選択肢に表示するために保存する。`Automatic` のときは空文字列 |
| `limitStyle` | 文字列 | 任意 | 利用枠の表示スタイル `Gauges` または `Bars`。既存ファイルにない場合は `Gauges` として扱う |

## 保存と読み込みの規則

- ファイルがないときは、取得元を `Local`、接続先 URL は空、認証トークンは未設定、表示先は `Automatic`、利用枠の表示スタイルは `Gauges` として扱います。
- 保存は、同じディレクトリの一時ファイルへ書いてから置き換えます。置き換えに成功した時点を保存の確定とし、失敗したときは既存のファイルを残します。
- `Local` の保存では Hub の接続情報を要求しません。保存済みの `connection` があれば暗号化された値を保持します。
- `Hub` の保存で認証トークンの入力が空なら、保存済みのトークンを復号して、新しい接続先 URL と組にして暗号化し直します。
- ファイルを読めないとき、または復号できないとき（別の Windows ユーザーや別の PC でコピーしたファイルなど）は、エラーを返します。ファイルは上書きも削除もしません。
- 表示スタイルの保存は、取得元・接続設定・表示先の保存値を変えません。同じファイルの1回の置き換えで、ほかの項目は現在の値を保ちます。
- 接続先 URL と認証トークンの平文は、ファイルにもログにも書きません。

## 更新ファイル

配置は `%APPDATA%\io.github.nuitsjp.token-monitor-turzx\updates\update-<ランダムな名前>\<インストーラーのファイル名>` です。環境変数 `WAILS_DATA_DIR` を指定した場合は、そのディレクトリ直下の `updates` に置きます。更新情報（`update.json`）は保存せず、メモリにだけ持ちます。

- 起動後に新版の確認を始める前に、`updates` を中身ごと削除します。前回の起動で残ったファイルは使いません。
- インストーラーは新しく作ったフォルダーへ書き込み、サイズと SHA-256 のハッシュが更新情報と一致した時点で取得済みとします。失敗したときや途中で止まったときは、そのフォルダーを削除します。
- 適用の直前に、置いたファイルのサイズとハッシュをもう一度確かめます。一致しなければ適用しません。

## tokscale のディレクトリ

配置は `%APPDATA%\io.github.nuitsjp.token-monitor-turzx\tokscale\` です。環境変数 `WAILS_DATA_DIR` を指定した場合は、そのディレクトリ直下の `tokscale` に置きます。

- 取得元が `Local` のとき、アプリが実行する tokscale の子プロセスにだけ、環境変数 `TOKSCALE_CONFIG_DIR` としてこのディレクトリを渡します。アプリ自身のプロセスの環境変数は変えません。
- 中身の形式は tokscale が決め、アプリは読み書きしません。利用状況の集計結果をアプリが書き込むこともありません。
- 解析をやり直さずに済むよう、再起動や取得元の切り替えでは削除しません。ディレクトリがなければ、最初の実行の前に作ります。
- Cursor の認証情報と API のキャッシュは tokscale の仕様によりこのディレクトリの外に置かれるため、アプリは扱いません。

## 探索先ファイル

配置は `%APPDATA%\io.github.nuitsjp.token-monitor-turzx\local-scan.json` です。環境変数 `WAILS_DATA_DIR` を指定した場合は、そのディレクトリ直下に置きます。`tokscale clients --json` はログ全体を解析するため実行の負荷が大きく、その結果のうちローカル取得が使う部分だけを保存して、起動のたびに実行しないようにします。

| キー | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `paths` | 文字列の配列 | 必須 | 監視する探索先の絶対パス。`clients --json` が返した Cursor 以外の探索先のうち、取得時にフォルダーとして存在したもの |
| `clients` | 文字列の配列 | 必須 | 既知のツールの識別子。保存時点で `graph --no-spinner` の `summary.clients` に現れていたもの |

- 取得元が `Local` で起動したとき、ファイルがあれば `paths` を監視し、`clients --json` は実行しません。ファイルがないとき、または読めないときは `clients --json` を実行します。
- `clients --json` を実行したあと、最初に成功した `graph --no-spinner` の結果と合わせて保存します。保存は、同じディレクトリの一時ファイルへ書いてから置き換えます。
- `graph --no-spinner` の `summary.clients` に、`clients` にないツールが現れたら、新しいツールを使い始めたものとして `clients --json` を1回実行し、監視する探索先を入れ替えてから保存し直します。実行中や保存し直す前に重ねては実行しません。
- 起動時の `clients --json` が失敗したときは監視なしで動かし、次回の起動で取り直します。
- 利用状況の値は保存しません。取得元の切り替えでは削除しません。
- 既に使っているツールのログの置き場所が変わっても、ツールの一覧が変わらないので検知しません。このファイルを削除してアプリを起動し直すと、探索先を取り直します。
