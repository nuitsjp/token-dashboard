# Styleを追加する

- 種別: 主成功
- UI確認: 要

## 開始条件
追加するスタイルのIDが、組み込みと取り込み済みの定義に存在しない。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | テーマ作者がStylesを開き、Add styleでフォルダーを指定する | 定義、寸法、表示データ構成、テンプレート、CSS、素材参照、IDの重複を検査する。合格したフォルダーを内部へコピーし、確定した定義を一覧へ加える。現在の表示スタイルは変更しない |
| 2 | テーマ作者がStylesで追加したカードを確認する | 名前と、そのスタイルで描いたプレビューを本来の縦横比で表示する。Built-inは表示しない |
| 3 | テーマ作者がDisplayを開き、対応するOutputと追加したスタイルを選ぶ | Outputに対応する候補だけを表示する。選択の保存成功後、そのスタイルで描き直して実機とプレビューへ反映する |
| 4 | 取得元の利用状況が更新される | 選択したスタイルを維持して最新値を描く。ページの保持と巡回は、対応する表示シナリオに従う |
| 5 | テーマ作者がアプリを終了して再起動する | 内部コピーから定義と選択を復元する。Styles画面を開かなくても描画を開始する。表示先と適合している追加スタイルは維持する |

## 受け入れ条件
- `theme.json`の形式版は1とし、IDと名前は空でないものとする。
- 受け入れる寸法と`dataLayout`は次の組み合わせに限る。

| 寸法 | `dataLayout` |
| --- | --- |
| 1920×462 | `gauges`または`bars` |
| 480×320、320×480 | `service-gauges`または`service-bars` |

- 既存の1920×462のファイルで`dataLayout`が省略されている場合は`gauges`として扱う。3.5インチでは明示を必須とする。未知の値や寸法との不一致は拒否する。
- テンプレートとCSSは指定フォルダー直下の`.hbs`と`.css`とする。既存の素材解決規則を維持し、フォルダー外のファイルはコピーしない。
- IDは内部の単一ディレクトリー名として使えるものとし、組み込み・取り込み済み定義との重複を拒否する。
- 内部コピーの確定後に候補と一覧へ公開する。追加元を変更・削除しても、取り込んだ定義には影響しない。
- フォルダー選択の取消では、定義、設定、画像を変更しない。
- 形式・寸法・表示データ構成・参照ファイル・素材が不正な場合は、定義へ追加せず、`This folder is not a valid style.`を表示する。
- IDが重複する場合は、追加せず、`This style id is already defined.`を表示する。
- コピーに失敗した場合は、その取り込みの一時ファイルを残さず、`Could not copy the style into the app.`を表示する。
- 取り込み処理中は重複操作を受け付けない。
- Displayの候補と機種間の自動補正は[3.5インチ表示シナリオ](../../利用状況をUSBディスプレイに表示する/scenarios/3.5インチでサービスごとの利用枠を順番に表示する.md#表示先と向き)に従う。適合する追加スタイルを機種の既定スタイルへ戻さない。
- 追加スタイルの選択は既存の`limitStyle`へIDで保存する。他の設定を変更しない。保存失敗時は操作前の設定、画像、ページ、巡回期限を保持する。
- 3.5インチ用追加スタイルでも、既存のPage interval、サービス選択、スキップ、個別枠、反転、位置シフト、離席消灯を使用する。
- 選択中の内部コピーが消失・破損して読み込めない場合は、エラーを表示し、不適合な画像を送信しない。設定を既定値へ上書きせず、取得処理とアプリの動作を継続する。
