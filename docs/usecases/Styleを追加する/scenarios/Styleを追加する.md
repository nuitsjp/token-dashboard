# Styleを追加する

- 種別: 主成功
- UI確認: 要

## 開始条件
アプリに `Gauges` と `Bars` があり、追加する `id` はまだ定義にない。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | テーマ作者が `Styles` を開き、`Add style` でフォルダーを指定する | 指定したフォルダーの直下に `theme.json` があるものとして検査する。形式版が1、`id` と `name` が空でなく、寸法が 1920×462、テンプレートがフォルダー直下の `.hbs`、スタイルシートがフォルダー直下の `.css`、`id` が既存と重複せず、テンプレートとスタイルシートが参照する画像が規則を満たすとき、そのフォルダー配下のファイルを相対パスのままアプリ内部の定義置き場へコピーし、表示スタイルの定義に加える。定義の `id` と `name` は `theme.json` の値にする。コピー後に追加元フォルダーを変更しても、内部のコピーは変えない。`Styles` の一覧は、その時点の定義で作り直す |

## 受け入れ条件
- 追加した定義はアプリの表示スタイルの定義に含まれ、`id` と `name` は `theme.json` と一致する。アプリを終了して再起動しても、その定義は残る。
- `Gauges` と `Bars` は定義に残る。
- フォルダーの外にあるファイルはコピーしない。
- フォルダー選択を取り消したときは、定義も内部のファイルも変えない。
- 検査に不合格のときは、定義に加えず、内部へコピーしない。`This folder is not a valid style.` を表示する。不合格になるのは、`theme.json` が直下にない、形式版が1でない、`id` または `name` が空、寸法が 1920×462 でない、テンプレートまたはスタイルシートがフォルダー直下の `.hbs` または `.css` でない、画像参照がローカルの対応形式でない、のいずれかである。
- `id` が既存の定義と重複するときは、定義に加えず、内部へコピーしない。`This style id is already defined.` を表示する。
- コピーに失敗したときは、定義に加えず、その取り込みでコピーしたファイルを残さない。`Could not copy the style into the app.` を表示する。
