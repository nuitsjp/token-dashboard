# 起動時に取得した新版で更新して再起動する

- 種別: 主成功
- UI確認: 要

## 開始条件
GitHub Releases の最新リリースが、実行中のアプリより新しい版である状態で、アプリが起動する。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者が Windows にサインインする | アプリを起動し、起動処理とは別にバックグラウンドで、最新リリースの `update.json` を取得して署名を検証する。実行中の版より新しいので、インストーラーを取得してサイズとハッシュを検証し、ユーザーごとのデータ領域に置く |
| 2 | インストーラーの取得と検証が終わる | タスクトレイのメニューに `Update and restart (v0.2.0)` を追加する。ウィンドウを開いている場合は、その場で更新の区画を表示する |
| 3 | 利用者がタスクトレイのアイコンをクリックする | ウィンドウを表示し、先頭に更新の区画を表示する。区画には `Version 0.2.0 is ready to install.` と `Update and restart` ボタンを表示する |
| 4 | 利用者が `Update and restart` を押す | 置いたインストーラーのサイズとハッシュを検証し直す。インストーラーを起動して引き渡し、`Exit` と同じ終了処理（受信の停止、TURZX への再起動の指示）でアプリを終了する |
| 5 | インストーラーがアプリの終了を確認する | アプリのファイルとサインイン時の自動起動の登録を更新し、新版のアプリを起動する |
| 6 | 利用者がタスクトレイのアイコンをクリックする | ウィンドウを表示する。ウィンドウのタイトルは `Token Dashboard v0.2.0` で、更新の区画とメニューの更新項目は表示しない |

## 受け入れ条件
- 新版の確認は起動時に1回だけ行う。確認と取得は自動で行い、適用（インストールと再起動）は利用者の操作があったときだけ行う。
- タスクトレイのメニューの `Update and restart (v0.2.0)` を押した場合も、手順4と同じ処理を行う。
- 最新リリースが実行中の版と同じか古い場合、更新の区画とメニューの更新項目は表示しない。
- 確認・取得・検証が失敗した場合（通信できない、リリースがない、署名やハッシュが一致しない）は、更新の区画とメニューの更新項目を表示せず、ログに原因の分類だけを書く。取得途中のファイルは削除する。再確認は次の起動時に行う。
- 手順4の再検証が失敗した場合は、アプリを終了せず、更新の区画に `The update could not be verified. It will be checked again at next startup.` を表示する。
- 起動したインストーラーの画面は表示しない（サイレント実行）。
- 更新後も、接続設定と表示先の選択はそのまま使える。
