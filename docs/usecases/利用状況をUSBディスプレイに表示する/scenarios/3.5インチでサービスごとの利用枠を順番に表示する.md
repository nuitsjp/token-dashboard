# 3.5インチでサービスごとの利用枠を順番に表示する

- 種別: 拡張
- UI確認: 要

## 分岐条件

利用者がDisplay画面で3.5インチ用の標準スタイルを選択するか、不適合なスタイルから3.5インチ用の既定スタイルへ自動で切り替わる。
実機への表示には、対応するTURZX 3.5インチが表示先として選ばれている。

## 手順

| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者がDisplayのOutputで3.5インチを選ぶ | 表示先と、必要なスタイル補正をまとめて保存する。不適合なら`Gauges 3.5" Landscape`へ切り替える。Styleの候補を対応するスタイルに絞り、選択中の名前を表示する |
| 2 | 利用者が3.5インチ用スタイルと180度反転の有無を選ぶ | 保存成功後に、選んだ寸法と配置で描き直す。Style区画のスタイル選択の下、プレビュー画像の上に`Page interval`を表示する。取得前は値を含まない待機表示を出す |
| 3 | 取得元が利用状況を報告する | サービス別の表示対象を構成し、先頭の対象ページを実機とプレビューに表示する。複数ページある場合は自動で巡回を始める |
| 4 | 利用者がService contentを開き、サービスのON/OFFと表示内容を選ぶ | 保存成功後に対象ページを再構成する。OFFにしても最後の表示内容を保持する |
| 5 | 利用者がDisplayの`Page interval`に秒数を入力してEnterを押すか、入力欄から離れる | 有効な秒数なら保存して反映する。現在ページを保ち、新しい間隔で時間を数え直す。複数ページある場合は、設定時間ごとに次へ進み、最後から先頭へ戻る |
| 6 | 取得元が利用状況を更新する | 最新値で描き直す。表示中のページが残る場合は、そのページと巡回期限を保持する |
| 7 | 利用者が個別利用枠の表示、非表示を変更する | サービス設定を変えずにページを再構成する。現在ページがなくなった場合は、従前の並びで次に残っているページを表示する |
| 8 | 利用者がUSBを抜き差しする | 切断中も取得、プレビュー、巡回を続ける。Automaticの選択先が変わった場合は候補と適合性を更新し、不適合なら機種の既定スタイルへ切り替えて保存する。再接続後は適合する最新ページを送る |
| 9 | 利用者がウィンドウを閉じる | ウィンドウを隠し、取得と表示を続ける。接続先変更によるスタイル補正も続ける |
| 10 | 利用者がアプリを終了して再起動する | 保存した設定を復元し、表示先との適合性を確認する。不適合なら機種の既定スタイルへ切り替えて保存し、先頭ページから表示を再開する。現在ページと巡回期限は保存しない |

## 受け入れ条件

### 表示先と向き

- 対応対象はUSB `1A86:5722`、識別文字列`USB35INCHIPSV2`の機器とする。現在のCOMインターフェースを機器識別子から解決し、COM番号を固定しない。
- 出力は1台とする。Automaticは対応機器を識別子順に選ぶ。明示選択した機器が未接続でも、その機器の選択を保持する。
- 横480×320、縦320×480と、それぞれの180度反転に対応する。横縦は標準スタイル、180度反転は出力設定で選ぶ。
- 180度反転はページ内容と配置を変えず、プレビューの文字を正立させる。
- Styleの選択候補は、表示先が対応する描画寸法と、スタイルの幅・高さが一致するものだけとする。3.5インチでは480×320または320×480、9.2インチでは1920×462を候補とする。対応しないスタイルを候補に表示しない。
- Automaticでは実際に選ばれた機器に合わせて候補を絞る。接続機器がなければ全候補を表示し、保存済みスタイルを維持する。
- 明示選択した機器が未接続でも、機器識別子から対応寸法を判定して候補を絞り、必要なスタイル補正を行う。識別できない場合は候補を表示せず、警告する。
- 起動時、Outputの変更時、Automaticの選択先変更時に、選択中のスタイルと表示先の適合性を確認する。
- 不適合なら、3.5インチは`Gauges 3.5" Landscape`（ID `gauges-35-landscape`）、9.2インチは`Gauges`（ID `gauges`）へ切り替えて保存する。直前のスタイルがBarsであっても同じ既定スタイルを使う。
- 適合しているスタイルは維持する。3.5インチのPortraitやBarsを手動で選択した後は、再起動や同じ機種への再接続で既定スタイルへ戻さない。
- Style欄は選択中の名前を通常の文字色で表示し、枠線、選択矢印、フォーカス表示によって操作できることを示す。通常時はマウスとキーボードで候補を選べる。
- 保存中、候補取得失敗中、候補がない場合だけStyle欄を無効にする。候補がない場合は`No compatible styles`を表示する。
- 表示先を識別できない場合、既定スタイルが利用できない場合、補正の保存に失敗した場合は、適合しない画像を機器へ送らない。保存済み設定とプレビューを保持し、警告またはエラーを表示する。
- 自動補正は保存成功後に表示へ反映する。通常表示中は補正後の先頭ページを表示し、離席中は補正後の寸法に合う黒画像を送る。
- 接続先の変化は既存の2秒ごとの確認で検出する。ウィンドウを閉じている間も自動補正を行う。
- 接続先とスタイルが適合したままなら、候補の再取得だけで設定、画像、ページ、巡回期限を変更しない。
- 候補の取得失敗はエラーとして表示し、再取得に成功するまでスタイルを選択できない。
- Styles画面では全スタイルを比較でき、Outputによる候補の絞り込みは行わない。

### 巡回間隔の設定

- 3.5インチ用スタイルの選択中は、Style区画のスタイル選択の下、プレビュー画像の上に`Page interval`を表示する。
- 取得前、表示対象がない場合、対象が1ページの場合も入力欄を表示し、あらかじめ設定できるようにする。
- 入力欄は秒単位の数値入力だけとし、プリセットや巡回のON/OFFは設けない。
- 5〜3600秒の整数を受け付け、未設定時は10秒を表示する。
- 入力欄の近くに`Pages switch automatically when there is more than one page.`と表示する。
- Enterを押すか入力欄から離れた時に保存する。範囲外、空欄、小数は保存せず、入力欄を保存済みの値に戻す。
- 保存に成功したときは完了の表示を出さない。保存に失敗した場合は保存前の値に戻し、入力欄の近くにエラーを表示する。
- 保存中は重複した保存操作を受け付けない。
- キーボードで操作でき、狭い画面でも入力欄や説明が横にはみ出さない。
- 3.5インチ用4スタイルとLocal／Hubで、同じ3.5インチ用の間隔を使う。
- 9.2インチ用スタイルの選択中は、この入力欄を表示しない。

### サービスの選択

- Service contentはサービス表示用スタイルの選択中に表示し、Display画面を開いたときは閉じた状態とする。
- 開閉はキーボードで操作でき、支援技術へ状態を伝える。閉じているカード内へフォーカスを移さない。
- 開閉状態は画面内だけで保持する。開閉操作では保存や巡回のリセットを行わず、データ更新と設定保存でも開閉状態を変えない。
- 一覧取得と保存のエラーは、閉じていても見える位置に表示する。
- サービスは利用枠と、3期間のTokensまたは推定コストの内訳に現れたIDから列挙する。利用枠のないサービスも選択できる。
- 各カードにサービス名、ON/OFF、Both／Limits／Tokensを置く。未設定はONかつBothとする。
- OFFでは最後の表示内容を表示したまま3択を無効にする。ONに戻すとその内容を復元する。
- 操作にはサービスを識別できる名前を付け、キーボードで操作できるようにする。保存中は重複した保存操作を受け付けない。
- 長いサービス名は折り返す。カード一覧は利用可能幅660px以上で2列、それ未満で1列とする。画面全体を縦スクロールでき、横にはみ出さない。

Localでは次の組だけを同じサービスとして扱う。

| サービス名と設定上の識別名 | Tokensの取得ID |
| --- | --- |
| Claude | claude |
| Codex | codex |
| Amp | amp |
| Antigravity | antigravity |
| Copilot | copilot |
| Grok Build | grok |
| Kimi | kimi |
| Warp/Oz | warp |

- Hubと未知のIDは、大文字小文字を区別した完全一致で扱う。類似名やモデル名による推測は行わない。
- `Antigravity`と`antigravity-cli`、`OpenCode Go`と`opencode`は統合しない。
- この対応付けはサービス表示用データの構成に限る。大型表示と既存の個別枠識別子は変更しない。

### 個別利用枠

- サービス表示用スタイルのUsage Limitsには、契約全体のToggleを置かず、提供元、契約名、個別枠の選択を表示する。
- サービスのON/OFFと表示内容は、個別枠の選択から独立させる。どちらを変更しても、もう一方の選択を変更、削除しない。
- `showMeter=false`の枠と、利用者が非表示にした枠をページ構成から除く。

### 表示内容と配置

- Tokensには、そのサービス全体のToday、Month、Allのトークン数と推定コストを表示する。契約別集計として扱わず、併記時もサービス全体の値であることを示す。
- 全体集計、モデル別集計、類似サービスの値から補完しない。未報告値は`—`、報告された0は0とする。
- トークン数はカンマ区切りで省略せず、コストはUSDの小数点以下2桁とする。大きな値は文字サイズを調整し、K／Mへの短縮や末尾省略を行わない。
- Bothでは、横向きはTokensを左、利用枠を右に、縦向きはTokensを上、利用枠を下に置く。片方だけの場合は、その内容に広く領域を割り当てる。
- Tokensのみでは、サービスごとに1ページとする。契約ごとに同じ値を繰り返さない。
- 利用枠を含むページは1サービス、1契約とし、サービス名、アイコン、契約名、必要な枠グループ名、残量、リセットまでの時間を表示する。未同梱のサービスには頭文字のアイコンを使う。
- Gaugesは1ページ最大3円とする。mainと同じグループ分類と期間順を使い、同じグループの枠を1円に最大2枠重ねる。異なるグループは重ねない。
- Bothで3円の場合は2列2段とし、上段左、上段右、下段中央の順に配置する。1〜2円の場合は、横向きでは縦並び、縦向きでは横並びとする。Limitsのみでは、横向きは横並び、縦向きは縦並びとする。
- Barsは1ページ最大3枠とし、枠名、残り時間、残量、バーを表示する。枠名と時間の書式はmainに合わせる。
- 超過する円や枠は後続ページへ送り、省略しない。ページ番号を表示する。
- 残量不明は`—`とし、残量の円弧やバーを描かない。リセット時刻不明も`—`とする。色とペースの判定はmainの共通規則を使う。
- 数値、見出し、図形、残り時間、ページ番号を重ねず、表示領域内に収める。

### ページ構成と巡回

- 利用枠を報告したサービスは報告順とする。同じサービスが複数回現れた場合は最初の位置を使う。Tokens内訳だけのサービスは、その後へサービスID順に加える。
- サービス内の契約は、表示対象枠の最小残量が少ない順とする。同値は報告順、不明だけの契約は最後とする。
- 3.5インチ用スタイルでは巡回を常時ONとする。9.2インチ用のCycleの保存値には従わない。
- 複数ページある場合は、3.5インチ用の間隔で順番に表示する。1サービスだけをONにしていても、そのサービスが複数ページに分かれる場合はすべて巡回する。
- 対象が1ページの場合は、そのページを維持する。
- データ更新では、サービス、契約、ページ内の枠によって同じページを識別し、巡回期限をリセットしない。
- 現在ページがなくなった場合は、従前の並びで次に残っているページへ進む。従前のページがすべてなくなった場合は先頭に戻る。
- サービスのON/OFF、表示内容、スキップ、手動または自動によるスタイルの変更では先頭から巡回を開始する。個別枠とデータの更新では上記の保持規則を使う。
- Page intervalの変更では現在ページを保ち、新しい間隔で時間を数え直す。スタイル補正を伴わない表示先の変更と180度反転だけの変更では、ページと巡回期限を変えない。
- Settingsの9.2インチ用CycleとCycle timeの変更では、3.5インチの現在ページと巡回期限を変更しない。
- 更新時と少なくとも1分ごとに描き直す。位置シフトによる再描画も巡回期限を変更しない。

### スキップと対象がない場合

- スキップ設定の表示名は`Skip full 5h or missing limits`とし、既定OFFとする。
- ONの場合、表示対象の利用枠が1つもないサービスを除外する。利用枠が未報告の場合に加え、`showMeter=false`と個別の非表示指定を適用した結果、対象枠が0件になる場合も含む。
- ONの場合、表示対象の5h枠が1つ以上あり、それらすべての残量が数値として正確に100%のサービスも除外する。
- Both／Limits／Tokensのすべてに同じスキップ判定を適用する。
- 5h判定は`windowMinutes`を優先し、未報告の場合はmainの`kind`対応表を使う。丸めた表示値では判定しない。
- 表示対象の利用枠がある場合、5h枠がないことだけでは除外しない。対象5h枠に残量不明がある場合、いずれかの契約の対象5h枠が100%未満の場合も除外しない。
- スキップによってサービスのON/OFF、表示内容、個別枠の選択を変更しない。設定一覧からサービスを取り除かない。
- 最新データで対象枠が報告され、スキップ条件を満たさなくなったサービスは表示対象に戻す。ページと巡回期限はデータ更新時の保持規則に従う。
- 取得失敗や一時的な欠落に対して、既存の取得処理が前回の利用枠を保持している場合は、その保持値で判定する。
- OFFの場合は、この設定によるサービスの除外を行わない。
- 取得前は値を含まない待機表示とする。報告サービスがなければ`No services to display`、すべてOFFなら`No services selected`、ONの対象がすべてスキップされたら`All services skipped`を表示する。
- スキップされず、Limitsを含む設定で対象枠がないサービスには、サービス名と`No usage limits to display`を表示する。BothならTokensも併記する。

### 保存と通信

- 各操作は1回の保存として処理し、成功後に表示へ反映する。失敗時はエラーを表示し、操作前の設定、画像、ページ、巡回期限を保つ。
- 3.5インチ用の間隔は`serviceCycleSeconds`へ保存する。未設定時は10秒とし、既存の9.2インチ用の間隔から引き継がない。
- 既存の`cycle`と`cycleSeconds`は9.2インチ用として保持する。3.5インチ用の間隔の保存で変更しない。
- スタイルを含む保存要求では、保存時点の表示先との適合性を確認する。存在するスタイルが不適合なら、機種の既定スタイルへ補正して保存する。存在しないスタイルIDはエラーとする。
- Output変更に伴うスタイル補正は、Outputと同じ1回の保存で確定する。起動時やAutomaticの接続先変更時の補正は、既存設定の`limitStyle`だけを変更する。
- 補正が不要なら設定を書き換えない。機種別のスタイル履歴や設定項目は追加しない。
- サービスの一時的な欠落、取得元や別設定の変更、自動スタイル補正で、保存したサービス設定と3.5インチ用の間隔を失わない。
- スキップ設定は既存の`presentation.skipFull5h`に保存し、未設定はOFFとする。保存済みのONには、利用枠がないサービスの除外も適用する。
- mainの既存設定を保持し、参考版専用の旧形式移行は行わない。
- 通信断は取得、プレビュー、巡回を止めない。再接続時に古い送信待ち画像を再生せず、最新ページを送る。
- 表示先、寸法、スタイルが変更された後に、旧設定で生成した画像を新しい表示先へ送らない。
- 大型標準スタイルの配置、ページ番号保持、個別枠の契約Toggle、WinUSB通信は維持する。
