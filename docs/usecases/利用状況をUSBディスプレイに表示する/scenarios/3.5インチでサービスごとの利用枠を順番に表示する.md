# 3.5インチでサービスごとの利用枠を順番に表示する

- 種別: 拡張
- UI確認: 要

## 分岐条件

起動時または表示先の変更時に、表示先としてTURZX 3.5インチ（`1A86:5722`、`USB35INCHIPSV2`のUSBシリアル機種）が選ばれる。

## 手順

| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者がアプリを起動するか、`Display`の`Output`で3.5インチを選ぶ | 機器に合う表示へ切り替える。取得前は取得元に応じた待機表示を出す |
| 2 | 取得元が利用状況を報告する | Localの既知のサービス表記を対応付け、表示がONのサービスから、サービス別Tokens、利用枠、または両方を最初の対象ページに表示する |
| 3 | 設定した切り替え時間が経過する | 次の対象ページへ進む。同じサービスの続きを表示してから次のサービスへ進み、最後から最初へ戻る |
| 4 | 利用者が必要に応じて`Service content`を開き、サービスのON/OFF、表示内容、向き、切り替え時間、スキップ設定、表示スタイルを変更する | 検証・保存後に表示へ反映し、最初の対象ページから巡回を再開する。サービスをOFFにしても最後の表示内容を保持する。保存失敗時は従前の設定と表示を保つ |
| 5 | 取得元が利用状況を更新するか、利用者が個別枠の表示・非表示を変更する | Tokensと利用枠を最新値へ更新する。表示中のページが残れば維持し、なくなれば次の対象ページへ進む |
| 6 | 利用者がウィンドウを閉じる | ウィンドウを隠し、取得と巡回表示を続ける |
| 7 | 利用者がアプリを終了して再起動する | 終了時に機器へリセットを指示して接続を閉じる。再起動時は保存したサービスのON/OFF、表示内容、その他の設定で表示を再開する |

## 受け入れ条件

- 対応機器を既存の`Output`に識別できる名前で表示する。USB機器識別子から現在のCOMインターフェースを解決し、COM番号には固定しない。
- 出力は1台とする。`Automatic`は対応する接続機器を識別子順に選ぶ。明示選択した機器が未接続でも選択を保持し、別機器へ切り替えない。
- 向きは`Landscape`、`Landscape (180°)`、`Portrait`、`Portrait (180°)`。横480×320、縦320×480、既定は`Landscape`とする。
- 上下逆の選択肢は実機の方向だけを180度変更する。通常の向きとページ内容・配置を共通にし、プレビューの文字は正立させる。
- `Display`の3.5インチ用設定に、折りたたみ可能な`Service content`を設け、その中にサービスごとのカードを表示する。サービスは利用枠とトークン内訳の報告から列挙し、利用枠のないサービスも選べるようにする。
- Localでは、次の対応表の利用枠名とTokensの取得IDを同じサービスとして列挙する。同じサービスのカードを重複させず、利用枠とTokensを同じカードで選べるようにする。

  | 統合後のサービス名・設定キー | Tokensの取得ID |
  | --- | --- |
  | Claude | claude |
  | Codex | codex |
  | Amp | amp |
  | Antigravity | antigravity |
  | Copilot | copilot |
  | Grok Build | grok |
  | Kimi | kimi |
  | Warp/Oz | warp |

- 対応表はLocalの3.5インチにだけ適用する。Hubと未知のIDは大文字小文字を区別した完全一致を維持する。モデル名、似た名前、一律の小文字化による対応付けは行わない。`Antigravity`と`antigravity-cli`、`OpenCode Go`と`opencode`は統合しない。
- `Service content`はDisplay画面を開いたときに閉じた状態とする。見出しと開閉を示す記号を表示し、見出しの操作で開閉する。キーボードでも操作でき、開閉状態を支援技術へ伝える。
- 開閉状態は画面内だけで保持し、設定ファイルへ保存しない。データ更新や表示設定の保存では開閉状態を変えない。開閉だけでは設定保存や巡回のリセットを行わない。
- 閉じている間はサービスカードを表示せず、カード内の操作へキーボードフォーカスを移さない。サービス一覧の取得エラーと保存エラーは、閉じていても見える位置に表示する。
- 各サービスカードは、上段にサービス名とサービス表示のON/OFF Toggle、下段に`Both`・`Limits`・`Tokens`の3択を持つ。3択はそれぞれ両方表示、利用枠のみ、Tokensのみに対応する。
- 未設定のサービスはONかつ`Both`とする。OFFのサービスは、利用枠とTokensの両方を巡回対象から除く。
- OFF時はサービス名と3択をグレーアウトする。3択は最後の選択を表示したまま操作を無効にし、ToggleはONへ戻せる状態を保つ。
- OFFにしても最後の表示内容を消さない。ONへ戻すとその内容で表示を再開する。アプリを終了・再起動してもON/OFFと最後の表示内容を復元する。
- Localの対応表にあるサービスは表の統合後の名前を表示し、その他は報告IDをそのまま表示する。長い名前は折り返す。カード一覧は利用可能幅660px以上で2列、それ未満で1列にする。向きと巡回間隔は利用可能幅520px以上で横並び、それ未満で縦並びにする。
- 3.5インチのDisplay画面は内容に応じて高さを確保する。`Service content`を開いた状態でもカードや操作欄を切り取らず、画面全体の縦スクロールで最後のサービスと個別枠まで操作できるようにする。横方向にはみ出さない。
- Toggleと3択はサービスごとに識別できる名前を持ち、キーボードで操作できる。保存中はサービスカードのToggleと3択を無効にする。
- 3.5インチの`Usage Limits`には契約単位のToggleを表示しない。提供元・契約名と個別枠のチップを表示し、枠ごとの表示・非表示を選べるようにする。
- サービスのON/OFF・表示内容と個別枠の選択は独立させる。OFFや`Tokens`へ変更しても個別枠の選択は消さず、個別枠の変更でサービスをONにしたり表示内容を変更したりしない。
- Tokensには、そのサービスの`Today`・`Month`・`All`のトークン数と推定コストを表示する。取得元が報告するツール単位で集計し、別ツールで使用した同じモデルの利用量は合算しない。
- Tokensはサービス全体の集計であり、契約別の集計として扱わない。利用枠と併記する場合も、サービス全体の値であることを表示する。
- Localの対応表にあるサービスは、対応するTokensの取得IDを使って値を読み取る。その他は報告IDの完全一致で対応付ける。対応する内訳や値が未報告の場合は`—`とし、全体集計や推測した値で補わない。明示された0は0として表示する。
- トークン数はカンマ区切りで省略せず、推定コストは大型版と同じUSD・小数点以下2桁の表記とする。桁数が大きい場合は文字サイズを調整し、数値の切り捨て、`K`・`M`への短縮、末尾省略を行わない。
- 両方表示の横向きではTokensを左、利用枠を右に配置する。縦向きではTokensを上、利用枠を下に配置する。片方のみの場合は、その内容に表示領域を広く割り当てる。
- Tokensのみの場合は、複数契約があっても統合後のサービスごとに1ページとする。同じサービスの合計値を契約ごとに繰り返さない。
- 利用枠を表示する各ページは1サービス・1契約とする。サービス名とアイコン、契約名（プラン名、なければアカウント名）、必要な枠グループ名、残量、リセットまでの時間を表示する。未同梱のサービスには現在の頭文字アイコンを使う。
- `Gauges`は1ページ最大3円とする。契約と枠グループによる分類は大型版と同じ規則を使う。枠グループは、枠の`label`から末尾の`5-hour`・`5h`・`session`・`weekly`・`daily`・`monthly`を大文字小文字を区別せず除いた部分とし、空になる場合は契約全体で1グループとする。
- 同じグループの枠を期間の短い順に並べ、1円に最大2枠まで外側から重ねる。期間不明の枠は最後に置く。3枠以上の同じグループは2枠ずつ円に分け、余りは次の円にする。異なるグループの枠は同じ円へ重ねない。円弧と色の規則は大型版と共通にする。3枠が報告された契約は、グループ化の結果にかかわらず1ページに収める。
- 利用枠とTokensの両方を表示し、円が3つある場合は、Landscape・Portraitとも上段に2円、下段中央に1円を置く2列2段とする。円の順序は上段左、上段右、下段とする。
- 円が1つまたは2つの両方表示では、Landscapeは縦並び、Portraitは横並びとする。利用枠のみでは、円の数にかかわらずPortraitは縦並び、Landscapeは横並びとする。180度の選択肢にも同じ配置規則を適用する。
- 縦配置では円の右側に必要なグループ名と、枠ごとの期間ラベル・時計記号・残り時間を置く。横配置と2列2段では円の下に置く。円の数と表示領域に合わせて大きさ、線幅、文字サイズを調整する。ゲージ中央の残量を太く、期間ラベルを小さく表示する。
- `Bars`は1ページ最大3枠とする。枠名は`label`、空なら`kind`を使う。枠名、リセットまでの残り時間、残量、バーを表示する。枠名の末尾省略と時間の書式は大型版のBarsに揃える。
- 数値、見出し、図形、残り時間、ページ番号を重ねたり、表示領域外へ出したりしない。
- 残量不明は`—`を表示し、残量の円弧・バーを描かない。リセット時刻不明も`—`とする。色によるペース・残量の判定は既存の共通規則を維持する。
- 利用枠を報告したサービスは報告順に巡回する。同じ統合後のサービスが複数回現れる場合は最初の報告位置を使う。トークン内訳だけに存在するサービスはその後へ追加し、統合後のサービスID順に並べる。
- サービス内の契約は表示対象枠の最小残量が少ない順、同値は報告順、不明のみの契約は最後とする。3円または3枠を超える場合だけ追加ページへ送り、省略しない。ページ番号を表示する。
- `showMeter=false`と利用者が非表示にした枠は、利用枠の表示対象から除く。
- 巡回間隔は5〜300秒の整数、既定10秒。対象が1ページならそのページを維持する。データ更新で切り替え期限をリセットしない。
- サービスのON/OFF・表示内容を含む表示設定の変更時はページを再構成し、最初のページから時間を数え直す。個別枠の選択やデータ更新で現在のページがなくなった場合は、生き残っている次のページへ進む。
- スキップは既定オフ。オンの場合、`showMeter`と個別枠の選択による対象5h枠が1つ以上あり、そのすべてが数値として正確に100%のサービスを除外する。Tokensのみを選んだサービスにもこの判定を適用する。スキップによってサービスのToggleや最後の表示内容を変更しない。
- 5h判定は`windowMinutes`を優先し、未報告時は既存の`kind`対応表を使う。丸めて100%になる値では判定しない。5h枠なし、5h残量不明、または複数契約・モデルのどれかが100%未満のサービスは除外しない。
- 取得前は値を含まない待機表示とする。報告されたサービスがない場合は`No services to display`、すべてのサービスがOFFの場合は`No services selected`、ONの対象サービスがすべてスキップされた場合は`All services skipped`を表示する。
- 利用枠を表示する設定のサービスに対象枠がない場合は、サービス名と`No usage limits to display`を表示する。Tokensも表示する設定なら同じページにサービス別Tokensを併記する。対象が復活したら通常の巡回へ戻る。
- データ更新時と少なくとも1分ごとに描き直す。Tokensだけの更新も、現在のページと巡回期限を維持したまま反映する。
- 実機とプレビューには同じ生成画像を使う。通信断は取得・プレビュー・巡回を止めず、再接続時はその時点の最新ページを送る。
- Localの対応表にあるサービスの保存設定は、統合後のキーが存在すればその値を使い、存在しなければTokensの取得IDのキーを使う。項目単位で両方の設定を混ぜず、選ばれたサービス設定全体に既存の未保存・`null`・旧Offの互換規則を適用する。
- サービスのON/OFFと表示内容は変更時に保存する。Localの対応表にあるサービスは統合後のキーへ保存する。旧キーは削除せず、Hubへ取得元を切り替えた場合も既存設定を失わないようにする。
- 1操作につき1回保存し、成功後に画面と表示へ反映する。サービスの一時的な欠落、取得元の変更、別の設定の保存では値を失わない。保存失敗時はToggle、3択、表示、巡回期限を従前の状態に保ち、エラーを表示する。
- 既存の`Both`・`Limits`・`Tokens`はONの同じ表示内容として引き継ぐ。既存の`Off`はOFFとして引き継ぐ。旧形式の`Off`には以前の表示内容が残っていないため、3択は`Both`を初期値とする。
- 9.2インチの表示、配置、選択順、通信、Usage Limitsの契約Toggleは変更しない。3.5インチ用のサービス設定とID対応表は9.2インチに適用しない。
- 完成系監査は変更済みデスクトップアプリと3.5インチ実機で行う。LocalのCodex・Claudeが重複しないこと、Bothで利用枠と正しいTokensが併記されること、Tokensのみで1サービス1ページになること、設定の引き継ぎ、折りたたみ、Toggleと3択、個別枠との独立性、4方向・両スタイル、巡回、プレビューとの一致を確認する。
