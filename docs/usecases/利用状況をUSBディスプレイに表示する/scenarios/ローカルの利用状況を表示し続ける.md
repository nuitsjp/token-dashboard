# ローカルの利用状況を表示し続ける

- 種別: 拡張
- UI確認: 不要

## 分岐条件
アプリの起動時に、保存済みの取得元が `Local` である（取得元の保存値がない場合を含む）。主成功の「利用者が Windows にサインインし、アプリが起動する」操作から、Hub の受信の代わりにこの系列へ分岐する。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者が Windows にサインインする | アプリを起動してタスクトレイに常駐し、同梱の tokscale でこの端末の利用状況の取得を始める。Today・Month・All の集計と利用枠の最初の取得がそろうまでは、利用状況の値を含まない `Waiting for local usage` の表示画像を TURZX に表示する |
| 2 | 集計と利用枠の最初の取得がそろう | 取得した利用状況をメモリ上の最新状態にし、主成功と同じ配置の表示画像を生成して、TURZX とプレビューに表示する |
| 3 | 利用者が AI ツールを使い、この端末の利用記録が追加・変更される | 変更を検知して集計と利用枠を取得し直し、TURZX とプレビューの表示を更新する |
| 4 | 利用記録の変更がないまま時間が経過する | 利用枠を定期的に取得し直し、別の端末での利用や枠のリセットを表示に反映する。Cursor の同期が有効な場合は Cursor の利用状況も定期的に取り込む |
| 5 | 日付または月が変わる | 利用記録に変更がなくても、新しい日付・月で Today・Month を集計し直して表示する |
| 6 | 利用者が取得元を `Hub` に変えて保存する、またはタスクトレイのメニューの `Exit` を押す | 利用記録の監視、定期取得、実行中の tokscale を止める。`Hub` に変えた場合は主成功の Hub の受信に切り替え、`Exit` の場合は主成功と同じ手順で終了する |

## 受け入れ条件
- トークン数は tokscale が集計した入力・出力・キャッシュ読み取り・キャッシュ書き込みの合計とし、reasoning のトークンは含めない。推定コストは tokscale が算出した値を使う。
- Today・Month は、tokscale と同じタイムゾーンの日付・月で区切る。
- 利用記録が取得元に反映済みで通信が正常なら、変更から表示の更新まで1分以内とする。Cursor の API 側で反映を待つ時間は含めない。
- 連続した変更はまとめて集計し、集計と利用枠の取得をそれぞれ同時に複数実行しない。
- 利用記録の変更がない間も、利用枠を前回の取得から45秒ごとに取得し直す。
- Cursor の同期は、起動時の同期結果で次のとおり扱う。認証画面や入力待ちは開かない。
  - 同期に成功した場合: 45秒ごとに同期し、同期後に集計し直す。
  - 認証情報がない場合: Cursor を使っていないものとして扱い、定期同期をしない。同じエラーを繰り返し記録しない。
  - 通信障害などで失敗した場合: 待ち時間を延ばしながら再試行する。
  - 起動後に Cursor へログインした場合と、同期成功後に認証が失効した場合は、アプリの再起動で判定し直す。認証の失効後は定期同期をやめる。
- Cursor を使っていない場合や Cursor の同期に失敗した場合も、ほかのツールの集計と利用枠の取得は続ける。
- 集計と利用枠は、それぞれ取得に成功した時点で表示へ反映し、一方の失敗や遅れで他方の反映を止めない。取得に失敗した値は0で表示せず、前回の表示値を保つ。失敗しても直ちに再実行を繰り返さない。
- 取得した内容が前回と同じなら、表示を更新し直さない。残り時間を更新する1分ごとの描画は、主成功のとおり続ける。
- tokscale の設定・解析キャッシュは、アプリのデータ領域にある専用のディレクトリに置き、利用者が別途インストールした tokscale とは共有しない。
