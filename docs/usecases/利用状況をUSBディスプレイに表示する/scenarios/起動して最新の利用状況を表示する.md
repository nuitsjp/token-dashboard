# 起動して最新の利用状況を表示する

- 種別: 主成功
- UI確認: 要

## 開始条件
利用者が Windows にサインインし、アプリが起動する。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者が Windows にサインインする | アプリを起動してタスクトレイに常駐し、保存済みの接続設定で Hub の受信を始める。最初の snapshot を受信するまでは、利用状況の値を含まない `Waiting for Hub` の表示画像を TURZX に表示する |
| 2 | Hub が snapshot を送る | 受信した利用状況をメモリ上の最新状態にし、上端に Tokens を横に並べ、その下に Usage Limits を円弧のゲージで描いた表示画像を生成して TURZX に表示する |
| 3 | 利用者がタスクトレイのアイコンをクリックする | ウィンドウを表示し、プレビューに TURZX と同じ最新の表示画像を表示する |
| 4 | Hub が利用量の変化を stats で送る | 最新状態を置き換えて表示画像を生成し直し、TURZX とプレビューの表示を同じ画像に更新する |
| 5 | 利用者がウィンドウの閉じるボタンを押す | ウィンドウを隠す。受信と TURZX の表示は続ける |
| 6 | 利用者がタスクトレイのメニューの `Exit` を押す | 受信を止め、TURZX に再起動を指示して起動直後の表示に戻し、アプリを終了する |

## 受け入れ条件
- 表示画像の上端に、Tokens の Today・Month・All を、左端の40pxの余白から横に並べる。期間ごとに、期間名、トークン数（`12,345,678` のようにカンマ区切りで、略さない）、推定コスト（USD）をこの順に並べ、期間どうしの間隔は一定にする。
- Usage Limits は、Hub が報告した契約（`providers` の各要素）ごとに角丸の枠のパネルにまとめ、`showMeter` が真の枠を持つ契約だけを、Tokens の下に、表示画像の全幅（左右の余白を除く）で、左端から左詰めで表示する。パネルの上端に、提供元のアイコン、提供元の名前（`provider`）、その右にプラン名（`planLabel`、空なら `accountLabel`）を並べた1行を見出しとして置く。パネルは、Tokens の下から下端まで、上下の余白を等しくとって置く。
- 提供元のアイコンは、`claude`・`codex`・`cursor`・`grok`・`opencode`・`antigravity`・`gemini` の7つをアプリに同梱する。同梱していない提供元は、アイコンを置かず名前だけを表示する。
- 契約は、表示する枠のうち残量の割合が最も小さい枠の値が小さい順に並べ、同じ値なら Hub が送った順とする。残量の割合がない枠は順番の計算から外し、表示する枠のどれにも割合がない契約は最後に回す。パネルは左から横に1段で並べ、パネルは含む円の数だけの列幅を使う。円の大きさは固定とする。
- Usage Limits の左右の外側余白は各40pxを既定とする。既定の余白で収まらない契約を追加表示できる場合は、左右の余白を同じ量だけ、必要最小限削る。余白の最小値は0pxとする。契約の並び順を保ち、先頭から表示できる契約数を最大にしたうえで、その契約群が収まる最大の左右同幅の余白を、0〜40pxの整数で使う。余白を削っても表示契約数が増えない場合は各40pxを維持する。左右各0pxでも収まらない契約から先は表示しない。
- 円1つの列幅は240px、同じ契約内の円の列間隔は12px、契約パネルの内側余白は左右各10px、契約パネル間の隙間は14pxとする。7つの円がすべて別契約の場合は、パネル群の幅が1904pxとなり、左右の外側余白を各8pxとして7契約すべてを表示する。
- 枠の長さ（分）は、Hub が送る `windowMinutes` を使う。なければ `kind` の固定表（`session`=300、`daily`=1,440、`weekly`=10,080、`billing`=43,200）を使い、どちらもなければ長さ不明とする。枠ラベルは長さから決め、1日未満は `5h`、1日以上は `7d`、約1か月（28〜31日）は `1mo` とする。長さ不明の枠は `kind` の名前をそのまま表示する。
- 円は、契約×枠グループごとに1つ作る。枠グループは、枠の `label` から末尾の枠名（`5-hour`・`5h`・`session`・`weekly`・`daily`・`monthly`、大文字小文字を区別しない）を除いた部分とし、除いて空になる場合は契約全体で1グループとする。1つの円には枠を最大2つ、長さの短い順に外側から重ねる。長さ不明の枠は最後に置く。1つのグループに枠が3つ以上あるときは、長さ順に2つずつ円に詰め、余りは同じグループの次の円にする。枠が1つの円は外側に1本だけ描く。
- 円弧は、下を開けた270度で、端を丸め、背景の円弧に重ねて、残量の割合に比例した長さを開始位置（左下）から時計回りに描く。円の中心に、各枠の「残量の割合と枠ラベル」を1行ずつ（枠が1つなら1行、2つなら2行）置く。枠グループが複数ある契約だけ、円弧の下の切り欠きに枠グループ名を1行置く。円の下に、枠ごとに1行を置き、左から枠ラベル、時計の記号、リセットまでの残り時間を並べる。残量の割合がない枠は円弧を描かず、中心に `—` を置く。リセット時刻がない枠の残り時間は `—` とする。推定上限額と月換算額は表示しない。
- 円弧の色は、ペースと残量の規則でそれぞれ状態（正常・注意・危険）を判定し、悪い方を採用する。正常は紫 `#9085e9`、注意は黄 `#fab219`、危険は赤 `#f0616d` とする。
  - ペースの規則: ペースは「残量の割合 ÷（理想の残量 × 100）」で、理想の残量は「リセットまでの時間 ÷ 枠の長さ」（0〜1に収める）とする。0.8以上で正常、0.5以上0.8未満で注意、0.5未満で危険とする。長さ不明、リセット時刻なし、理想の残量が0の枠は正常とする。
  - 残量の規則: 残量の割合が40を超えると正常、25以上40以下で注意、25未満で危険とする。
- リセットまでの残り時間は、1日未満なら `2h 13m`、1時間未満なら `13m`、1日以上なら `3d 4h` の形式で表示する。
- 受信がなくても、表示画像を1分ごとに生成し直し、残り時間を更新する。
- 最初の snapshot を受信するまでは、利用状況の値を表示しない。
- stats を受信したら、TURZX とプレビューの表示を同じ内容に更新する。
- TURZX へは、1920×462 の表示画像を時計回りに90度回転した Baseline JPEG（品質85）で送る。
- ウィンドウを隠している間も、TURZX の表示は更新し続ける。
- インストーラーの完了ページの「起動して画面を表示する」（既定でオン）で起動したときだけ、ウィンドウを表示する。Windows へのサインイン時の起動は、ウィンドウを隠してタスクトレイに常駐する。
- `Exit` で終了したあと、TURZX は起動直後の表示に戻っている。
